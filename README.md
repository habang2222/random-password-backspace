# Random Backspace — 키 입력 추론 방어 아이디어

## 1. 생각하게 된 계기

[RadKey 논문](https://arxiv.org/pdf/2606.10148)을 읽다가 한 가지 생각이 들었다.

이 논문은 키보드를 직접 해킹하지 않고도 타이핑할 때 발생하는 진동과 소리를 이용해 사용자가 입력한 문자를 추론하는 기술을 다룬다.

그렇다면 **공격자가 어떤 키를 눌렀는지 알아내더라도 실제 입력된 내용을 정확하게 알 수 없도록 만들면 어떨까?**

여기서 아이디어가 시작됐다.

## 2. 랜덤 백스페이스

일반적으로 백스페이스를 한 번 누르면 문자 하나가 삭제된다.

그런데 백스페이스를 누를 때마다 **1개, 2개, 3개 중 무작위 개수의 문자가 삭제**되도록 하면 어떨까?

예를 들어 다음과 같다.
```
입력: ABCDE

Backspace 1회

1개 삭제 → ABCD
2개 삭제 → ABC
3개 삭제 → AB
```

공격자가 `ABCDE`를 입력하고 백스페이스를 한 번 눌렀다는 사실까지 알아내더라도, 실제로 몇 글자가 삭제되었는지는 알 수 없게 되는 것이다.

백스페이스를 여러 번 사용하면 가능한 삭제 조합도 증가한다.

물론 실제 입력 내용이나 사용자의 행동에 따라 결과를 추론할 가능성은 남아 있다.

## 3. 비밀번호 입력창에만 적용

모든 입력창에서 이런 기능을 사용하면 너무 불편할 것 같았다.

그래서 비밀번호 입력창에만 적용하는 방법을 생각했다.

웹사이트에서는 일반적으로 비밀번호 입력창을 다음과 같이 정의한다.
```xml
<input type="password">
```

이 속성을 확인하면 복잡한 AI 분석 없이도 비밀번호 입력창을 구분할 수 있다.

따라서 크롬 확장 프로그램으로 만들어 구글, 네이버 등 여러 웹사이트에서 사용할 수 있을 것 같다.

추가로 사용자가 몇 글자가 삭제되었는지 알 수 있도록 입력창 근처에 `2글자 삭제` 같은 안내 메시지를 표시하면 좋을 것 같다.

## 4. 실제로 효과가 있을까?

자연어는 문맥으로 어느 정도 추론할 수 있지만, 숫자와 특수문자가 섞인 무작위 비밀번호는 상대적으로 추론하기 어려울 것 같다.

다만 몇 가지 문제가 있다.

- 백스페이스를 사용하지 않으면 효과가 없다.
- 공격자가 화면까지 볼 수 있다면 삭제 개수를 확인할 수 있다.
- 사용자가 지워진 문자를 다시 입력하는 과정에서 추가 단서를 제공할 수 있다.
- 무작위 삭제 때문에 비밀번호 입력이 불편해질 수 있다.

결국 이 방법이 실제로 얼마나 효과적인지는 실험해 봐야 한다.

## 5. 마무리

처음에는 단순히 백스페이스로 지워지는 글자 수를 랜덤하게 바꾸면 어떨까 하는 생각이었다.

생각해 보니 비밀번호 입력창에만 적용하면 일반적인 사용에는 큰 영향을 주지 않을 것 같았고, 크롬 확장 프로그램으로도 구현할 수 있을 것 같았다.

**핵심은 키 입력 자체를 숨기는 것이 아니라, 공격자가 알아낸 키 입력과 실제 남아 있는 문자열 사이에 불확실성을 만드는 것이다.**

실제로 얼마나 효과가 있을지는 모르겠지만, 한번 구현해 볼 만한 아이디어라고 생각한다.

## 설치

1. 이 폴더를 원하는 위치에 보관합니다.
2. Chrome 주소창에서 `chrome://extensions`를 엽니다.
3. 오른쪽 위 **개발자 모드**를 활성화합니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 `random-password-backspace` 폴더를 선택합니다.
5. 이미 열려 있던 웹페이지는 새로고침합니다. 확장 프로그램을 고친 뒤에는 `chrome://extensions`에서 해당 확장 프로그램의 새로고침 버튼을 누르고 웹페이지도 새로고침합니다.

## 사용과 설정

비밀번호 입력창에 커서를 두고 Backspace를 누르면 커서 바로 앞의 완성된 글자 단위로 최대 3개가 삭제됩니다. 남은 글자가 더 적으면 그만큼만 삭제합니다. 알림에는 선택된 난수가 아닌 실제 삭제 수가 `1글자 삭제`처럼 표시됩니다. 삭제할 글자가 없으면 알림도 표시하지 않습니다.

확장 프로그램 아이콘을 클릭하면 기능 ON/OFF, 삭제 개수 알림 ON/OFF, 알림 표시 시간(300~5000ms)을 설정할 수 있습니다. 기본값은 기능 ON, 알림 ON, 1500ms입니다. 설정은 `chrome.storage.local`에 저장되며, 열린 웹페이지에도 변경이 전달됩니다. OFF에서는 브라우저의 원래 Backspace 동작을 사용합니다.

선택 영역이 있는 경우, Ctrl/Alt/Meta/Shift 조합키를 누른 경우, IME 조합 중인 경우에는 브라우저와 사이트의 기존 동작을 유지합니다. 일반 텍스트·이메일·검색 입력창에는 적용하지 않습니다. `readonly`와 `disabled` 입력창에도 적용하지 않습니다.

## 동작 방식

- `keydown`을 이벤트 위임으로 감지하므로 나중에 생성된 비밀번호 입력창도 처리합니다. 실제 이벤트 경로와 현재 포커스를 확인합니다.
- `crypto.getRandomValues()`에서 1바이트를 뽑고 255는 다시 뽑습니다. 나머지 255개 값은 1, 2, 3에 각각 85개씩 대응하므로 세 결과는 균등합니다.
- 가능한 경우 `Intl.Segmenter`로 한글 자모 결합, 이모지 등을 grapheme cluster 단위로 나눕니다. 커서가 글자 내부에 강제로 놓인 경우 그 글자의 일부는 자르지 않습니다.
- 사이트가 취소할 수 있는 `beforeinput`을 한 번 전달한 다음, 네이티브 `setRangeText()`로 값을 수정하고 `input` 이벤트를 한 번 전달합니다. React 등에서 DOM 값과 내부 상태를 동기화하는 데 필요한 경로이지만 모든 사이트가 합성 이벤트를 받아들이지는 않습니다.
- 알림은 `position: fixed`와 `pointer-events: none`을 사용하여 페이지 레이아웃과 클릭을 건드리지 않습니다. 화면 가장자리를 고려해 위치를 조정하며, 연속 입력 시 내용과 타이머를 갱신합니다. 포커스가 벗어나면 제거합니다.

## 직접 확인

1. 확장 프로그램을 설치한 뒤 웹페이지를 새로고침합니다.
2. 일반 텍스트 입력창에서 Backspace가 한 글자씩 지워지는지 확인합니다.
3. 비밀번호 입력창에서는 1~3글자가 삭제되고 알림 숫자가 실제 삭제 수와 같은지 확인합니다. 한 글자만 남았을 때, 문자열 중간에 커서가 있을 때, 일부 문자를 선택했을 때도 확인합니다.
4. 팝업에서 기능과 알림을 끄고 켜며, 변경한 설정이 새로고침 후에도 유지되는지 확인합니다.
5. 실제 로그인 화면에서는 입력·삭제와 사이트의 값 인식 여부를 확인합니다. 무작위 삭제 때문에 제출 전 입력 내용을 다시 확인해야 할 수 있습니다.

개발 과정에서 Chrome for Testing 155.0.8059.84로 자동화 항목 **24/24**, Naver 화면의 더미 입력·삭제 항목 **1/1**을 통과했습니다. 로그인 성공은 확인하지 않았고 Google 로그인 화면은 시험하지 않았습니다.

## 권한과 개인정보

요청하는 확장 API 권한은 `storage` 하나입니다. 모든 일반 HTTP/HTTPS 사이트의 비밀번호 필드를 자동 처리하려면 `content_scripts.matches`가 `http://*/*`와 `https://*/*`를 포함해야 하므로 설치 화면에 넓은 사이트 접근 범위가 나타납니다. Chrome의 사이트 접근 설정에서 범위를 제한하면 해당 사이트에서만 동작합니다. 스크립트는 기본 `ISOLATED` 환경에서 실행됩니다.

비밀번호 값은 삭제 범위를 계산하는 동안에만 읽고 수정합니다. 비밀번호, 키 입력 이력, 삭제 이력은 저장하거나 콘솔에 출력하거나 서버로 전송하지 않습니다. 저장되는 것은 `enabled`, `showNotice`, `noticeDuration` 설정뿐입니다. 외부 라이브러리·원격 JavaScript·분석 서비스·네트워크 호출은 사용하지 않습니다. 알림에는 삭제 개수만 들어갑니다.

## 알려진 호환성 및 보안 한계

- 일반 HTML password input을 대상으로 합니다. 사이트가 자체 제작한 입력 UI를 사용하거나 비밀번호 필드가 닫힌 Shadow DOM 안에 있으면 감지하지 못할 수 있습니다. 열린 Shadow DOM은 이벤트의 `composedPath()`가 내부 입력창을 공개하는 범위에서 지원합니다.
- `all_frames`와 origin fallback으로 일반 iframe과 일부 `about:blank`/동적 프레임을 지원하지만, 브라우저가 확장 주입을 막는 sandbox 프레임·제한된 프레임까지 보장하지 않습니다. `chrome://` 같은 브라우저 내부 페이지와 Chrome 웹 스토어에는 주입할 수 없습니다. `file://` 주소는 현재 manifest의 적용 범위에서 제외했습니다. 시크릿 모드는 Chrome에서 별도로 허용해야 합니다.
- 사이트의 `beforeinput` 핸들러가 이벤트를 취소하거나 자체적으로 값을 바꾸면 확장 프로그램은 추가 삭제를 하지 않습니다. 사이트가 합성 `input` 이벤트(`isTrusted === false`)를 무시하거나 자체 키 이벤트·검증 로직에 의존하면 내부 상태와 값이 맞지 않을 수 있습니다. 특정 React 버전이나 모든 비밀번호 관리자와의 호환성을 보장하지 않습니다.
- 비밀번호 자동 완성 자체는 Backspace가 아니므로 변경하지 않지만, 자동 완성 직후 사이트의 상태 처리 방식에 따라 수동 삭제 결과가 달라질 수 있습니다.
- `Intl.Segmenter`가 없는 구형 Chromium에서는 코드 포인트 단위로 대체하며 결합 문자를 완전히 보호하지 못할 수 있습니다. 최신 안정 Chrome을 권장합니다.
- 이 구현은 **화면을 보지 못하는 음향·진동 관찰자**를 가정합니다. 삭제 개수 알림을 화면에서 볼 수 있는 사람, 화면 녹화·악성 확장·악성 사이트 스크립트·기기 침해자는 보호 대상이 아닙니다. 알림을 끄면 화면 노출은 줄지만 사용자가 실제 삭제 수를 확인하기 어려워집니다.
- 무작위 삭제가 공격자의 추정 정확도를 얼마나 낮추는지는 실험으로 검증되지 않았습니다. 입력 오류나 재입력 횟수 때문에 다른 정보가 생길 수도 있습니다. 이 기능을 비밀번호 관리자, 다중 인증, 기기 보안의 대체재로 간주해서는 안 됩니다.
- Backspace를 누르지 않는 입력에는 이 기능이 개입하지 않습니다. RadKey 또는 다른 부채널 공격을 대상으로 한 방어 효과도 측정하지 않았습니다.

향후에는 다양한 사이트·프레임워크·비밀번호 관리자에 대한 실측 호환성 검증과, 음향·진동 공격자에게 실제로 제공되는 정보량을 측정하는 실험이 필요합니다.
