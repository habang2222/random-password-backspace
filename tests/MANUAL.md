# 수동 확인표

자동화 테스트는 로컬 테스트 페이지와 헤드리스 Chrome에서 실행합니다. 아래 항목은 **실제 브라우저 창**에서 별도로 확인해야 합니다. 체크하지 않은 항목을 통과로 간주하지 마세요.

1. `chrome://extensions`에서 개발자 모드를 켜고 프로젝트 폴더를 압축해제된 확장 프로그램으로 로드한다.
2. 일반 텍스트, 이메일, 검색 입력창에서 Backspace가 기본 동작대로 한 글자만 지우는지 확인한다.
3. 비밀번호 입력창에 여러 글자를 입력하고 Backspace를 반복한다. 매번 1~3글자만 삭제되고 알림의 숫자가 실제 삭제 개수와 같은지 확인한다.
4. 비밀번호가 한 글자 또는 빈 문자열일 때 불필요한 삭제나 잘못된 숫자 표시가 없는지 확인한다.
5. 커서를 비밀번호 중간에 놓았을 때 뒤쪽 문자가 유지되고 커서가 삭제 지점에 남는지 확인한다.
6. 비밀번호의 일부를 드래그해 선택하고 Backspace를 누른다. 선택 부분만 기본 동작대로 지워지는지 확인한다.
7. 한글 완성형, 조합 중 입력, 결합 문자, 이모지 및 가족 이모지를 입력해 문자가 반으로 잘리지 않는지 확인한다.
8. `Ctrl+Backspace`, `Alt+Backspace` 등 조합키가 확장 프로그램의 무작위 삭제로 바뀌지 않는지 확인한다.
9. 알림이 입력창의 오른쪽 또는 아래에 표시되고, 화면 가장자리에서도 보이며, 클릭과 포커스를 방해하지 않는지 확인한다. 다크 모드와 라이트 모드도 각각 확인한다.
10. Backspace를 연속 입력해 알림이 갱신되는지, 설정한 시간이 지난 뒤 사라지는지, 입력창에서 포커스를 옮기면 즉시 사라지는지 확인한다.
11. 확장 프로그램 아이콘의 팝업에서 기능 OFF, 알림 OFF, 표시 시간을 변경한다. 새로고침 뒤에도 값이 유지되는지 확인한다.
12. 동적으로 열린 로그인 창, 일반적인 iframe 안의 입력창, 가능한 Shadow DOM 입력창에서 동작 범위를 확인한다.
13. 비밀번호 관리자의 자동 완성 직후 값이 확장 프로그램 때문에 바뀌지 않는지 확인한다. 자동 완성 후 직접 Backspace를 누르면 웹사이트가 변경된 값을 인식하는지 확인한다.
14. Google 및 Naver 로그인 페이지에서 **입력과 삭제 동작만** 확인한다. 실제 계정 로그인 성공은 별도 검증 없이는 주장하지 않는다.
15. Chrome 개발자 도구의 콘솔 및 네트워크 탭에서 비밀번호 원문 출력이나 외부 전송이 없는지 확인한다.

자동화 테스트 실행: 프로젝트 폴더에서 `node --test tests/*.test.mjs`. Node.js 24와 확장 프로그램 명령행 로드를 지원하는 [Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/) 또는 Chromium이 필요합니다. 테스트 러너는 `CHROME_PATH` 환경 변수, 이 프로젝트 이름의 임시 Chrome for Testing 캐시, 시스템 Chromium 순서로 실행 파일을 찾습니다. 일반 Chrome 137 이상은 명령행 확장 로드 플래그를 지원하지 않으므로 이 자동화에 사용하지 않습니다.

Naver 실사이트 입력 필드만 확인하려면 PowerShell에서 다음을 실행합니다. 더미 문자열만 입력하고 로그인 제출은 하지 않습니다.

```powershell
$env:LIVE_SITE_TESTS = '1'
node --test --test-name-pattern='Naver login' tests/integration.test.mjs
```
